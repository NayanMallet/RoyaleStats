# RoyaleStats — Design system

Ce Storybook documente l'interface de RoyaleStats en suivant l'**Atomic Design** : chaque niveau est construit à partir du niveau précédent.

| Niveau        | Rôle                                                                | Exemples dans RoyaleStats                               |
| ------------- | ------------------------------------------------------------------- | ------------------------------------------------------- |
| **Atoms**     | Plus petits éléments d'interface, sans logique métier               | Button, Input, Label, Avatar, Separator, Textarea       |
| **Molecules** | Groupe d'atomes qui remplit une fonction simple                     | FormField, SearchBar, InfoCard, UserMenu                |
| **Organisms** | Bloc autonome de l'interface, souvent branché sur l'API             | HowToFindTag, LinkedPlayer, MetaStats, LinkPlayerDialog |
| **Templates** | Mise en page qui place les organismes, avec du contenu factice      | AuthTemplate, DashboardTemplate                         |
| **Pages**     | Templates remplis avec du contenu réel (ici, des réponses simulées) | Login, Register, Profile                                |

## Où sont les fichiers

- Les composants restent à leur place : `src/components/ui/` (atomes et molécules générés par shadcn-vue), `src/components/` (organismes), `src/views/` (pages).
- Les stories sont rangées par niveau dans `src/stories/{atoms,molecules,organisms,templates,pages}/`.
- Les données factices et le mock d'API sont dans `src/stories/mocks/`.

## Simuler l'API

Aucune story n'appelle le vrai backend. Chaque story déclare les réponses dont elle a besoin :

```ts
parameters: {
  auth: 'linked', // 'guest' | 'user' | 'linked'
  mockApi: [{ method: 'GET', url: '/api/meta/snapshot', body: { snapshot } }],
}
```

Un appel non simulé répond `404` et affiche un avertissement dans la console : c'est le signe qu'il manque un mock.
On peut aussi simuler la latence (`delay`) ou une erreur (`status: 500`) pour documenter les états de chargement et d'erreur.

## Accessibilité

L'onglet **Accessibility** (addon a11y) analyse chaque story avec axe-core. Les violations sont signalées sans bloquer (`test: 'todo'`) tant que la dette existante n'est pas résorbée.
